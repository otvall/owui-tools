# Подготовка сабагента внутри Router Pipe

Переносим подготовку сабагента из отдельной Subagent Preparation Filter Function внутрь Router Pipe, чтобы подключение нового сабагента не требовало обязательного preparation attachment. Pipe уже выбирает модель и готовит её capabilities; он также будет выполнять проекцию Tool history, ограничения истории и установку Skill context при каждом вызове сабагента. Политики истории, capabilities и продолжения запроса сохраняются; проверка допустимых ID при загрузке Skills пересматривается ниже.

Решение заменяет [ADR 0001](0001-routed-model-preparation.md) в части обязательного фильтра сабагента и приоритета его подготовки. Router Preparation и самостоятельные фильтры для обычных моделей остаются в своих прежних ролях.

Подготовка сабагента всегда выполняется первой: проекция Tool history → ограничения истории → установка Skill context. Затем Pipe одним штатным вызовом Open WebUI запускает дополнительные inlet-фильтры модели. Они сохраняют собственный порядок между собой; настройка положения подготовки относительно них удаляется. Дополнительные фильтры получают уже подготовленный контекст, а их изменения не запускают повторную подготовку. Это сознательное изменение прежнего контракта порядка, устраняющее отдельный priority подготовки и разделение платформенной цепочки на два запуска.

Лимиты истории остаются общими для сабагентов и переезжают в Valves Pipe с прежними нулевыми значениями по умолчанию. Изоляция Tool history, свежий Skill context, продолжения текущей Tool-цепочки, capability reuse и откат подготовки при ошибке сохраняются.

Отладочные логи подготовки сабагента управляются общим `debug` Pipe. Отдельный переключатель диагностики прежнего фильтра удаляется; включение `debug` показывает логи маршрутизации и подготовки.

Вызовы `view_skill` используют штатный builtin Open WebUI во всех трёх путях: оркестратор, сабагент и самостоятельный Skill Context. Общая allowlist-обёртка, ограничивающая вызовы прикреплёнными Skills, удаляется. Существование, активность Skill и права пользователя проверяет Open WebUI. Skill manifest по-прежнему формируется из выбранных Skills; он помогает выбрать Skill, но не задаёт закрытый список допустимых ID. Загрузчик может получить другой активный Skill, доступный пользователю, даже если этот Skill отсутствует в manifest.

Передаваемая штатному builtin идентичность пользователя сохраняется: у оркестратора это Workspace Model owner, у сабагента — Execution user. У самостоятельного Skill Context сохраняется его существующая передача пользователя. Перенос и удаление allowlist не меняют этих ролей; штатные проверки доступа выполняются для переданного пользователя.

Дополнительная финальная проверка дублирования или подмены `view_skill` после сторонних фильтров не добавляется. Изменения дополнительных фильтров принимаются в рамках их обычного исполнения; Pipe не выполняет повторную подготовку или новый контроль загрузчика после них.

Актуальный обязательный комплект содержит Router Pipe, Router Preparation и `lite_delegate`. Отдельный `subagent_preparation.py` исключается из комплекта и генерации. Самостоятельные фильтры для обычных моделей остаются доступны. Версия с отдельным Subagent Preparation сохранена тегом `subagent-preparation-filter` в GitHub.

При обновлении пользователь сохраняет каталог и настройки Router Preparation
до замены кода, копирует `history_turns` и `history_tool_calls` прежнего
Subagent Preparation (либо Subagent Context) в общие Valves Pipe и выбирает
общий Pipe `debug`. Затем вручную снимает Subagent Preparation или заменяемые
им Tool Call Filter, Subagent Context и Skill Context, включая их global
attachments. Router Preparation остаётся на публичном Router с прежними
Valves и Global выключенным. Удаление `subagent_preparation.py` из репозитория
не удаляет установленную Function; её администратор может удалить отдельно
после снятия attachments. Специальное обнаружение, миграция, пропуск, удаление
оставшихся attachments и совместимость со старой конфигурацией не входят в
новую реализацию. Настройка нового сабагента сразу использует встроенную
подготовку Pipe.
