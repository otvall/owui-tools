# Объединённая подготовка моделей для Handoff

Для подключения нового сабагента сейчас требуется прикрепить три Filter Functions и сохранить их порядок. Согласованная цель — один фильтр подготовки на Workspace Model сабагента, сохраняющий внутренние этапы обработки. Подготовка остаётся прикреплённым к модели фильтром. Объединение ограничено сценарием Router и сабагентов: самостоятельные фильтры для обычных чатов сохраняются как необязательный набор.

Обязательный набор содержит две Filter Functions: подготовка Router объединяет Registry, Previous Tool Context и History Cleanup; подготовка сабагента объединяет Tool Call Filter, Subagent Context и Skill Context. Пользователь прикрепляет первый фильтр к Router, а второй — к каждой Workspace Model сабагента. Внутренний порядок этапов задаётся кодом, поэтому при подключении модели не нужно настраивать порядок этих компонентов через priorities.

Лимиты истории задаются общими Valves фильтра подготовки сабагента. Индивидуальные значения для отдельных моделей и копии фильтра ради разных лимитов не входят в согласованную цель. Выбраны две явные роли вместо одного универсального фильтра; это уменьшает число обязательных Filter Functions с шести до двух и attachments сабагента с трёх до одного, сохраняя отдельные внутренние этапы.

При одновременном прикреплении объединённого фильтра и заменяемых им старых фильтров подготовка завершается понятной ошибкой конфигурации с перечнем лишних attachments. Для перехода пользователь заменяет соответствующую тройку одним новым фильтром. Автоматического пропуска старых фильтров нет.

## Следствия

Объединяется устанавливаемый набор Functions. Внутренние этапы и общие исходники сохраняются отдельными модулями; готовые фильтры остаются самостоятельными файлами для загрузки в Open WebUI. Самостоятельные фильтры для обычных чатов устанавливаются при необходимости и не входят в обязательный Router-набор.

Фильтр подготовки Router сохраняет выбор базовых Tools/Skills и настройку справочной записи предыдущих Tool Calls. Фильтр подготовки сабагента содержит общие лимиты истории. У каждого объединённого фильтра есть общий priority относительно дополнительных сторонних фильтров; порядок внутренних этапов фиксирован.

Подключение нового сабагента по-прежнему включает настройку Workspace Model, выбор Tools/Skills/MCP и запись в реестре агентов. Объединение сокращает обязательную подготовку модели до одного attachment. При реализации требуется сохранить изоляцию Tool history по исполнителю, свежий Skill context, текущую Tool-цепочку и откат подготовки при ошибке.

## Статус обсуждения

Все перечисленные выборы согласованы в интервью; переход к подготовке спецификации подтверждён вызовом to-spec. Реализация не начата.

Спецификация опубликована в [GitHub Issue #12](https://github.com/otvall/owui-tools/issues/12).
