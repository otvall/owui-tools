# Saved HTML Widgets

Нативный Tool для Open WebUI **0.11.1**: агент находит HTML, сохранённый
предыдущим агентом, и получает исходный код для HTML-презентации. Спецификация:
[issue #21](https://github.com/otvall/owui-tools/issues/21).

## Установка

1. В Open WebUI откройте **Workspace → Tools → Create**.
2. Скопируйте весь [saved_html_widgets.py](saved_html_widgets.py) в редактор,
   задайте название **Saved HTML Widgets** и сохраните Tool. Для загрузки нужен
   только этот файл; соседние исходники и тесты не требуются.
3. Подключите Tool к Workspace Model агента презентаций и включите нативный
   вызов функций. В Handoff Router добавьте его к Tools выбранного сабагента
   обычным способом.

Tool экспортирует две операции. Open WebUI передаёт Execution user, текущий
чат и идентификатор пользовательского запроса через скрытые служебные
аргументы; модель не выбирает пользователя или чат.

## Минимальный сценарий

1. Попросите агента графиков построить график нативным Tool, который возвращает
   inline HTML. Дождитесь завершения ответа.
2. Отправьте **новый запрос** агенту презентаций в той же ветке чата:

   > Создай HTML-презентацию с уже построенным графиком. Сначала вызови
   > `list_saved_html_widgets`, просмотри все страницы и выбери нужный результат
   > по `message_id`, доступному заголовку и операции производителя. Передай
   > его `widget_id` в `read_saved_html_widget`. Используй возвращённый полный
   > HTML и исходные числа при сборке презентации.

`list_saved_html_widgets()` возвращает, например:

```json
{
  "status": "success",
  "widgets": [
    {
      "widget_id": "<returned identifier>",
      "message_id": "<source response>",
      "html_bytes": 1234,
      "title": "Продажи по месяцам",
      "producer_operation": "plot_sql_chart"
    }
  ],
  "has_more": false,
  "next_continuation": null
}
```

HTML не входит в listing. Ответы упорядочены от ближайшего предка текущего
запроса к более ранним, независимо от timestamps и других веток. В одном ответе
сначала идут message-level `embeds` в сохранённом порядке, затем native
`function_call_output` в порядке `output`, а внутри каждого — порядок `embeds`.
Каждое расположение получает отдельный идентификатор, даже если HTML или
заголовки совпадают.

`title` извлекается из сохранённого HTML `<title>`, если он присутствует.
`producer_operation` присутствует только у native output с однозначной
сохранённой связью `call_id` с `function_call`, содержащим имя операции.
Отсутствующие, пустые или неоднозначные сведения не заменяются догадками:
такие поля опускаются, а сам виджет остаётся доступным. Message-level embeds
не получают имя производителя из соседних вызовов. Заголовок описывает виджет;
для чтения всегда нужен `widget_id`.

`read_saved_html_widget(widget_id="<returned identifier>")` возвращает обычный
результат Tool:

```json
{"status": "success", "widget_id": "<returned identifier>", "html": "<complete original HTML>"}
```

HTML, встроенные данные, стили и скрипты становятся видны вызывающей модели.
Reader сохраняет исходные строки, Unicode, кавычки и переводы строк; отдельный
iframe не создаётся. Агент презентаций отвечает за выбор, размещение, размер и
сборку слайдов. Отсутствие вызова производителя в подготовленной Tool history
не мешает чтению: источником служит сохранённый чат.

Чтобы использовать **несколько виджетов**, выберите несколько идентификаторов
из каталога и вызовите `read_saved_html_widget` для каждого. Чтобы взять
**более ранний результат**, продолжайте discovery до нужного source response,
а не ограничивайтесь первым ответом или одним производителем.

## Страницы и ограничения

Администратор настраивает Valves самого Tool:

| Valve | По умолчанию | Значение |
| --- | --- | --- |
| `LIST_PAGE_SIZE` | `50` | Число виджетов на странице; положительное целое. |
| `MAX_HTML_BYTES` | `0` | Максимальный размер полного HTML в UTF-8 bytes; `0` отключает предел. |

Если `has_more=true`, передайте **без изменений** `next_continuation` в следующий
вызов `list_saved_html_widgets(continuation="<returned continuation>")`.
Повторяйте до `has_more=false`; последняя страница имеет `next_continuation=null`.
Пустой успешный каталог также имеет `has_more=false`.

Continuation проверяется по текущему чату, исходному пользовательскому запросу,
размеру страницы и сохранённому каталогу. Неверный, устаревший или перенесённый
из другого запроса continuation даёт `INVALID_CONTINUATION`: начните listing
заново без аргумента. Каждый следующий вызов заново проверяет права и ветку.
Continuation не предоставляет доступа к другому чату или ответу.

Ограничение чтения не скрывает виджет из каталога. Если его `html_bytes`
превышает `MAX_HTML_BYTES`, read возвращает `WIDGET_TOO_LARGE` с размером и
пределом, без HTML. Администратор может увеличить предел. Любой успешный read
возвращает исходный HTML целиком; reader не обрезает HTML и данные.

## Область чтения и ошибки

- Доступны message-level `embeds` и native `embeds` на структурированных
  `function_call_output` завершённых предыдущих assistant-ответов. Графики,
  таблицы, схемы, другие HTML-документы и фрагменты используют одни операции
  без семантической классификации и списка разрешённых производителей.
- Ветка определяется сохранёнными предками **пользовательского сообщения,
  начавшего текущий запрос** (`__metadata__.user_message_id`). Глобальный
  `currentId`, навигация в UI и подготовленная история модели не выбирают ветку.
  Текущий assistant-ответ может ещё отсутствовать в хранилище. Неполная,
  циклическая или противоречивая цепочка предков даёт явную ошибку.
- Ответы с `done=False` и текущий ответ исключены. Reader не читает runtime
  stream overlays и не обещает получить результат другого Tool до завершения
  того же запроса.
- Оба вызова заново проверяют актуального Execution user: владелец чата,
  разрешённый платформой администратор, shared-chat read grants или read-доступ
  к папке. Workspace Model owner не подставляется вместо пользователя.
- Идентификатор является локатором, а не разрешением. При чтении проверяются
  текущий чат, ветка, завершённость ответа и наличие того же HTML в выбранном
  расположении. Удалённый или изменённый embed требует нового listing.
- URL-only embeds исключены. Ссылки на ресурсы внутри сохранённого HTML остаются
  без изменений: reader не загружает ресурсы, не выполняет JavaScript, не
  проверяет offline-рендеринг и не меняет состояние графика или чата.
- Возвращается состояние, записанное в `embeds`: встроенные значения и ссылки
  остаются исходными. Более поздние изменения только в живом iframe не входят
  в этот снимок. Новое хранилище, миграция, browser access и изменение
  производителей, Router Handoff или Skill context не требуются.

Успешный пустой список —
`{"status":"success","widgets":[],"has_more":false,"next_continuation":null}`.
Ошибки имеют `status="error"`, `code` и понятное `message`, без HTML:

| Code | Причина |
| --- | --- |
| `CHAT_CONTEXT_MISSING` | Не передан текущий сохранённый чат. |
| `USER_CONTEXT_MISSING` | Не передан Execution user. |
| `ACCESS_DENIED` | Чат отсутствует или текущему пользователю запрещено его читать. |
| `BRANCH_CONTEXT_MISSING` | Отсутствует идентификатор исходного пользовательского запроса. |
| `BRANCH_CONTEXT_INVALID` | Запрос или его сохранённая цепочка предков противоречивы либо недоступны. |
| `WIDGET_UNAVAILABLE` | Идентификатор не указывает на доступный поддерживаемый виджет в этой ветке. |
| `INVALID_CONTINUATION` | Страница неверна либо каталог, запрос или настройки изменились; начните listing заново. |
| `WIDGET_TOO_LARGE` | Исходный HTML превышает настроенный предел; полный read не выполнен. |
| `STORAGE_UNAVAILABLE` | Не удалось прочитать платформенное хранилище; детали остаются в журнале сервера. |

## Проверка реализации

Тесты вызывают настоящие публичные методы Tools и заменяют только границу
хранилища и прав Open WebUI. Для локального запуска вне сервера требуется
SQLAlchemy 2.x и Pydantic 2.x:

```sh
python3 -m pip install -r saved_html_widgets/requirements-tests.txt
python3 -B -m unittest discover -s saved_html_widgets/tests -v
```

Проверяются list-then-read с пустой и сокращённой Tool history, точный HTML,
обе формы хранения, порядок ветки и source locations, optional metadata,
страницы, предел чтения, актуальные права и исчезнувшие виджеты. Реальный
[сохранённый SQL-график](../deployment/sql-demo-chat-result.json) читается среди
посторонних виджетов из native map и canonical `history.messages`; устаревший
placeholder в `chat.messages` не служит источником. SQLite-fixture также
подтверждает сохранность HTML с нулевым символом и неверного глобального
`currentId` после чтения.

В 0.11.1 удобные getters `Chats.get_chat_by_id_for_user` и
`Chats.get_messages_map_by_chat_id` могут записывать исправления истории.
Поэтому модуль использует read-only ORM-снимок `Chat`,
`ChatMessages.get_messages_map_by_chat_id` и ту же последовательность правил
доступа с платформенными `AccessGrants` и `has_folder_access`. Политика
сверена с [tagged getter 0.11.1](https://github.com/open-webui/open-webui/blob/v0.11.1/backend/open_webui/models/chats.py#L1731);
при обновлении Open WebUI её нужно сверять с новой версией платформы.

Для smoke check на работающем Open WebUI выполните минимальный сценарий выше:
после завершения графика новый запрос агента презентаций должен получить
исходный HTML в model-facing результате `read_saved_html_widget`. Сохранённые
browser-only изменения (например, скрытая в iframe кривая) не входят в этот
снимок.
